# QCA Spacetime Lab (Rust + WebAssembly SIMD)

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24450503.svg)](https://doi.org/10.5281/zenodo.24450503)

A zero-framework, high-performance computational laboratory written in **Rust + WebAssembly (`+simd128`)** with a native multithreaded CLI (`qsu_cli`) and standalone **Python/NumPy/SciPy** cross-verification scripts. It explores **quantum cellular automata (QCA)**, **Lorentz-violation phenomenology**, **2D causal-set quantum gravity**, and **1+1D tensor-network lattice QFT (DMRG / 2-site TDVP)**, alongside a real-time browser laboratory featuring **139 interactive experiments** and **194 automated Rust unit tests**.

## Repository Structure

- `src/`: Rust physics engine (`lib.rs`, `via_a_qca4.rs`, `via_b_causal_pt.rs`, `via_c_schwinger2f.rs`, `dmrg.rs`, `mps.rs`, `qgravity.rs`, `noncubic_pheno.rs`, `studies.rs`, `sm.rs`, `twd.rs`, etc.), native multithreaded CLI (`src/bin/qsu_cli.rs`), and 194 unit tests (`src/tests/`).
- `scripts/`: Standalone Python/NumPy/SciPy verification scripts (`verify_via_a_mlodinow_brun.py`, `verify_via_c_schwinger_exact.py`) and publication figure/table generator (`generate_publication_assets.py`).
- `datos_investigacion/`: Reproducible CSV/JSON outputs and 20 adaptive Parallel Tempering checkpoints.
- `figuras_publicacion/`: Publication-ready vector figures (`fig_via_{a,b,c}.{pdf,svg,png}`) and LaTeX summary tables (`tablas_latex.tex`).
- `index.html`: Zero-dependency ES-module WebAssembly interactive laboratory (139 experiments, bilingual `EN | ES` UI).
- [`RESEARCH_SUMMARY.md`](RESEARCH_SUMMARY.md): Self-contained **English technical summary** of Pathways A, B, and C (Phases 17–20, equations, verified tables, and referee-grade convergence/multi-seed audits).
- [`ANALISIS.md`](ANALISIS.md) and [`estudio_preguntas_abiertas.md`](estudio_preguntas_abiertas.md): Detailed Spanish physical analysis and Phase 17 study report across Phases 1–20.

## Quick Start (Build, Verify & Run)

```bash
# 1. Independent Python/NumPy/SciPy cross-verification (~5 s)
pip install numpy scipy matplotlib
python scripts/verify_via_a_mlodinow_brun.py
python scripts/verify_via_c_schwinger_exact.py
python scripts/generate_publication_assets.py

# 2. Native Rust test suites (Phases 18-20 ~20 s; full 194 tests ~3 min)
cargo test --release --lib tests::phase18
cargo test --release --lib tests::phase19
cargo test --release --lib tests::phase20
cargo test --release

# 3. Native multithreaded CLI (subcommands: phase15..phase20, pub-checks, via-a..via-c...)
cargo run --release --bin qsu_cli -- phase20
cargo run --release --bin qsu_cli -- pub-checks

# 4. WebAssembly SIMD interactive lab (must be served over HTTP, not file://)
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build --target web --release
node --check pkg/qca_spacetime_lab.js
python -m http.server 8080      # open http://localhost:8080
```

## Desviaciones explícitas de la especificación

- **Código en módulos.** La especificación pide un único `src/lib.rs`. El crate es una biblioteca con `src/lib.rs` como raíz y la API, y el resto del código en módulos (`walk.rs`, `seed.rs`, `analysis.rs`, `render.rs`…). Los tests de §5 están en `src/tests/`, que se incluye desde `lib.rs` con `#[cfg(test)]`. Con miles de líneas, un solo archivo no se puede mantener; el comportamiento y la API son los mismos.
- **Tope con tolerancia y cola FIFO.** El reparto de §2.5 actúa cuando E > E_cap·(1 + 5·10⁻⁷), y la lista de trabajo es una cola, no una pila. Sin la tolerancia, los excesos del orden del redondeo rebotan sin fin entre celdas que ya están en el tope. Con una pila, el primer paso tras inyectar una gota densa agotaba el límite de iteraciones. El test 17 (E ≤ E_cap·(1 + 10⁻⁶)) se cumple.
- **Brillo de la vista MIP.** La especificación fija b = (E_eff/E_max)^0,5. En la MIP 3D, el máximo de cada columna de fondo ya está cerca de E_max y todo sale brillante, así que el frontend usa el exponente 2 en esa vista (ajustable con un slider; `set_brightness_gamma`).
- **Masa de un solitón ante una fuerza lenta (§3.4, test 115, experimento 71).** El "1,32" de la especificación se reproduce (1,33) solo si el impulso se divide por la norma total de la caja, que incluye el ~20 % de radiación que no viaja con el solitón. Por unidad de norma del propio solitón, la fuerza lenta da la masa de banda (1,62 ≈ m\* = 1,64). El test comprueba las dos cosas, y ANALISIS.md lo explica.
- **Predicciones de la gravedad 2D.** El Φ "de la fuente sola" se calcula con el paquete inyectado, con toda su norma. Así sale la predicción de la referencia (1,27·10⁻⁵ en el test 19). Con la fuente relajada, que ya ha radiado parte de su norma, la predicción baja un 25 % y el test 19 no pasaría.
- **Causalidad (test 23).** La sonda es Φ a 40 celdas, como dice §5: la señal llega en t = 89. Con el gradiente de Φ llega antes (t = 73), por el tamaño de la masa.
- **Zitterbewegung (test 33, experimento 18).** Un paquete ↑ finito deriva a ⟨k²/E²⟩ ≈ 1/(2σ²m²) (0,031 celdas/paso con σ = 40 y m = 0,1; se mide 0,028). La especificación pide "sin deriva", pero esa deriva es física, así que el ajuste la incluye.
- **Materia en f32 y campos en f64 (§4.2).** Los tests de Gauss e invariancia gauge comprueban los umbrales "en f32" de §5 (por ejemplo, 10⁻⁴), no los de f64 (10⁻¹²). En la práctica el residuo queda en ~5·10⁻⁷. El test 106, que solo da el umbral en f64 (< 10⁻¹²), se comprueba con < 10⁻⁵.
- **El tope reparte en f64.** El reparto de §2.5 se hace sobre una copia sombra en f64 de las celdas tocadas y se redondea a f32 una sola vez. En f32 las transferencias pequeñas no se pueden representar: el montón de arena no convergía y la contabilidad de corrientes con U(1) dejaba un residuo de Gauss de 10⁻⁴.
- **Amortiguamiento fuera de los subpasos (test 107).** La especificación dice que amortiguar E una vez por paso, fuera de los subpasos, diverge en ~2000 pasos. Con este integrador no diverge. El test comprueba que el amortiguamiento va dentro de los subpasos y que el campo relajado coincide con la magnetostática de red (< 10⁻³).
